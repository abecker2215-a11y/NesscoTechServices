## 3. Changes Implemented

### 3.1 Canonical URLs — Relative → Absolute

**Problem:** 4 pages identified in the audit used relative canonical URLs, which can cause canonical resolution issues when pages are accessed via different protocols, hosts, or paths.

| File | Before | After |
|---|---|---|
| `src/app/[location]/page.tsx:78` | `canonical: "/${location}"` | `canonical: \`https://nesscotech.com/${location}\`` |
| `src/app/about/page.tsx:25` | `canonical: "/about"` | `canonical: "https://nesscotech.com/about"` |
| `src/app/pricing/page.tsx:16` | `canonical: "/pricing"` | `canonical: "https://nesscotech.com/pricing"` |
| `src/app/glossary/page.tsx:15` | `canonical: "/glossary"` | `canonical: "https://nesscotech.com/glossary"` |

**Why necessary:** Relative canonical URLs require the browser/crawler to resolve them against the current page URL. If a page is accessed via `http://` or a non-canonical host, the resolved canonical may differ from the intended absolute URL, causing duplicate content and link equity dilution.

**Before-and-after:** All 4 pages now declare absolute HTTPS canonical URLs matching the sitemap hostname.

### 3.2 Sitemap — Removed Build Timestamp from lastmod

**File:** `next-sitemap.config.js`

**Problem:** The `transform` function set `lastmod: new Date().toISOString()` for every URL, meaning all 612 URLs shared the identical build timestamp (`2026-11-05T00:01:47.xxxZ`). This does not represent actual meaningful content modification dates and provides no useful crawl signal to search engines.

**Before:**
```js
transform: async (config, path) => ({
    loc: path,
    changefreq: config.changefreq,
    priority: config.priority,
    lastmod: new Date().toISOString(),
}),
```

**After:**
```js
transform: async (config, path) => ({
    loc: path,
    changefreq: config.changefreq,
    priority: config.priority,
}),
```

**Why necessary:** The instruction requires lastmod to represent actual meaningful content modification dates, not the current build timestamp. Removing the hardcoded timestamp eliminates misleading data. `next-sitemap` postbuild regenerates `sitemap-0.xml` without lastmod entries (verified: 0 `<lastmod>` elements in regenerated file).

**Before-and-after:** Sitemap URLs no longer carry a uniform build timestamp. All 612 URLs remain in the sitemap.

### 3.3 Homepage Open Graph Image

**File:** `src/app/page.tsx`

**Problem:** The homepage Open Graph metadata had no `images` property, meaning no `og:image` was declared. Social sharing and some crawlers would lack a representative preview image.

**Before:** Homepage `openGraph` had no `images` array.

**After:** Added `images` array referencing existing public asset:
```js
images: [
  {
    url: "https://nesscotech.com/hero/homepage-hero.png",
    width: 1200,
    height: 630,
    alt: "Nessco Tech Services — Tampa Bay IT Support",
  },
],
```

**Why necessary:** Uses an existing branded image from `public/hero/homepage-hero.png`. No new image was generated or invented.

**Before-and-after:** Homepage now declares an OG image for social sharing and crawler preview.
